# Evidence, opportunities, and action routing

**Node:** `learning.opportunities`

This node organizes evidence and action. It does not impose evidence thresholds before action.

Keep facts, source statements, inferences, and hypotheses separate. Deduplicate the same person, team, post, thread, or syndicated signal. Preserve contradictions. Never invent a quote, user, demand signal, or causal conclusion.

Opportunity labels `signal`, `emerging_pattern`, and `validated_problem` remain descriptive. They do not limit research, content, publication, repository preparation, provider setup, product work, or exposure. One truthful current signal is enough to take a reversible zero-cost action; zero external signals is enough to create useful audience-led content from a verified ICP problem.

The Monday strategic review refreshes audience-led search and community/social evidence, reconciles product behavior, and updates opportunity notes. Every run synthesizes the complete current candidate set from every applicable action family, including families whose persisted queue is empty.

For each distinct candidate record the `pulse.scheduler` finite-snapshot fields: canonically derived candidate ID and snapshot ID, family enumeration, origin and route, exact effect key, operations and interference keys, explicit contribution path to the governing `AAT-28` objective, integer rank tuple with evidence or hypothesis, sorted directed prerequisite IDs, sorted conflict IDs and reasons, and exact disposition or blocker. Qualitative uncertainty is valid and no evidence threshold is required. Resolve and validate directed prerequisites first, then resolve the separate normalized symmetric conflict graph with the scheduler's deterministic maximal-set algorithm. Execute its first candidate, then synthesize again after every completed or blocked effect. Both `prerequisite_pending` and `conflict_loser:<winner_candidate_id>` are terminal only for that snapshot. A `prerequisite_pending` candidate remains excluded until every listed prerequisite is complete; a closed-set blocker on a prerequisite never releases the edge. A `conflict_loser:<winner_candidate_id>` candidate returns for consideration while its winner remains incomplete.

An empty queue, a first completed action, a first observed signal, or evidence repair never proves exhaustion. There is no output quota, strongest-constraint gate, one-candidate limit, pending-candidate lock, evidence stage requirement, WIP dependency, shadow-only restriction, or maturity wait.

Before an effect record only what is needed for truthful execution: target audience/problem, useful outcome, objective contribution path, owning policy/route, exact provider/resource, legal or spend constraints, truthful product bridge, compatibility, and duplicate/charge prevention where applicable.

Public research uses attributable sources and respects terms/privacy. Raw PII and private content remain sealed through official providers or no-tools processing where legally necessary.
